# A clear, respectful release

Use this checklist before you publish. The publisher dashboard shows the limits that apply to your account.

**Who this is for:** every author, before each release, and anyone who wants to know what the Skill Store accepts.

## Own what you share

Publish only code, images and other material that you have the right to distribute. Keep license notices and author credits from templates and dependencies. Do not use another publisher's app identity.

The template's license describes the rights you receive for that template. It does not grant rights to unrelated artwork, brands or services.

## Describe it honestly

Explain what changes, which software and APIs it needs, and any setup the owner must complete. Use an original name and clear release notes. Do not promise capabilities that the pack cannot provide.

Theme artwork must not depict Jibo's robot, shell, head, face or eye. Theme assets are passive images. They do not carry code, actions, external URLs or new permissions.

## Respect the owner

Keep permissions as narrow as the feature allows. Never put secrets, household information or account credentials into a pack, example, listing or screenshot.

A native app's install, update and removal need the owner's physical approval on Jibo. A theme cannot grant itself permission to run code or bypass safety controls.

## Check before sharing

- Validate the manifest and every listed asset.
- Check contrast and legibility on the intended background.
- Use your own registered app ID and a new version.
- Check the actual theme API support, not only a software version number.
- Keep licenses and attribution available with your project.
- Read the upload result before making the listing public.
