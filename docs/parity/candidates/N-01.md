# N-01 candidate: complete parser requests and named rule selection

Status: **working candidate; awaiting lead review**
Owner: Luna Max
Base: `b654de598255ba023f33ff31656bfa5bc84057d4`
Reference revision: `5c0a7390539663ba749d360de348a428c088505c`

This candidate routes HTTP parser requests through a request-scoped source
registry. The route passes the complete `data` object (`text`, `rules`, `loop`,
and `external`) to the parser. It trims and validates text, filters unknown
requested names, evaluates only the selected public rule handle, and reports
the selected rule in the NLU result. Public names come from the frozen
`rules_fst` inventory: 97 named handles plus the generated root `launch` union.
The 117 `.rule` files are source dependencies, so a source filename such as
`clock/launch` is not accepted as a public handle when the original registry
only exposes `launch.fst`; personal-report menu parsing uses the public
`main-menu/execute_personal_report` name. Empty, missing, unknown, and
no-match rule lists return the reference empty result (`entities: null`). Loop
member postprocessing runs after a match.

`packages/nlu/resources/rules-src` contains all 117 frozen `.rule` sources. The
`rule-inventory.json` manifest records every source path and SHA-256, the 98
compiled public handle names and their frozen FST hashes, and each source's
factory dependencies. All source files are parsed and a count mismatch or any
missing, changed, or malformed source throws a visible error. The dependency
inventory distinguishes six unsupported factory dependencies from two
bounded-compatibility grammars and five finite word-list dependencies. A named
public rule with an unsupported dependency fails visibly with an HTTP 500
instead of becoming an unexplained no-match; the `launch` union remains a
partial source-backed matcher and its dependency gaps are recorded in the
inventory. The timer grammar is a hand-authored compatibility resource pinned
to the reference `timer.fst` hash; it covers the ordinary hour/minute/second
forms needed by the request boundary and is not a regular-expression special
case or a claim of factory parity.

The same golden run confirms exact candidate outputs for `launch` joke and
personal-report/calendar/commute cases, including the source-specific

`handle:personal-report/launch`), and for the timer-local, timer-plus-launch,
duplicate-rule, empty, unknown, and known-plus-unknown boundaries.

The candidate does not claim N-02's complete cross-rule priority arbitration,
N-06's full contextual-name matrix, or N-07's external-agent/fallback
behavior. For non-empty text, a truthy `external` request follows the frozen
disabled-Dialogflow `null.external` error after result selection; falsey values
are ignored, and empty text returns the empty result before external handling.
Loop postprocessing follows the source detector's ordered entity/full-name/
first-name checks and skips users with absent name parts. The generated timer
grammar is intentionally bounded, and six factory dependencies remain
unsupported.
Broader factory parity and exact compiled-FST behavior remain lead-review work.

No corpus recapture, golden retagging, reference/consumer output, dependency
or lockfile change was made.
