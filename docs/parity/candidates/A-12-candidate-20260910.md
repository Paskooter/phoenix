## What each op does now (with source line anchors)

**PutEvents** — validates `events` (array, required), `deviceId`/`trackingId` (optional
strings) exactly as the source's Joi rules (`handlers/log.handler.ts` `@validatePayload`),
allows unknown members. Stamps each event with `deviceId`, `trackingId`, plus
`robotId`/`accountId` from the `x-amz-credentials` header when the gateway supplies it.
Level derivation is byte-for-byte the controller rule: missing/invalid level →
`message.includes("error") ? "error" : "info"`. Every event is appended as a JSONL record
to the durable sink (`events.jsonl`), mirroring the per-record S3 stream logger.
Responds with the real controller result string.

- **PutEventsAsync** — validates `kind ∈ {HEALTH, LOG}` and `serial` (string, required).
Throttle gate `probability > Math.random()` (env `ETCO_log_probability`, default 1 —
the config default) → `REQUEST_THROTTLED` 429 when the draw fails. On success returns
`{ contentEncoding: "gzip", uploadUrl }` with the source's `log-async/robot=…/serial=…/
account=…/year=…/month=…/day=…/kind=…/<ms>.gz` key layout, uploadUrl pointing at the
local PUT sink.

- **NewKinesisCredentials** — no payload validation; `ROBOT_ONLY` 403
(`"Request forbidden. Only robotd are allowed."`) when no robot identity
(`x-amz-credentials` has no `friendlyId`), exactly like the handler's `ROBOT_ONLY`
gate. Kinesis/STS are dead in Phoenix: with a robot identity present it returns a
shape-complete StsCredentials (all four required members) with an already-expired
`Expiration` so the robot's telemetry degrades to "no streaming" instead of crashing on a
missing member.

- **PutBinary** — the one raw-body op (`options: { binary: true }`): reads the request
  stream directly (like Hapi's `/binary` route with `output: "stream"`), `trackingId`
  read from the `x-tracking-id` header, stores under
  `log-binary/<accountId>/<trackingId>/<uuid4>` and returns `{ path, url }` where `url`
  is a retrievable GET. Throttled like the controller.

- **PutBinaryAsync** — validates optional `trackingId` string; throttled; returns
  `{ path, url, uploadUrl }` with a fresh uuid4 per handshake (S3-style independent
  objects, so producer retries after a failed handshake never collide).

- **PutAsrBinary** — validates `trackingId` (required string) and `metadata` (object);
  per-source ASR sampling gate is the exact Java `hashCode % 10000 <= bound` rule; key
  layout `asr-binary/year=…/month=…/day=…/accountId=…/trackingId=…/<ms>.bin`; returns
  `{ bucketName, key, metadata, uploadUrl }` with metadata echoed.

- **SetLevel** (logadmin) — `@parseCredentials({ adminOnly: true })` faithfully ported:
  without `isAdmin` in `x-amz-credentials` → `AUTHORIZED_UNDER_ADMIN` 401; validates
  `friendlyIds` (string array) and `namespaces` (`{ namespace: string, level ∈ npm enum }`
  array); returns `{ result: "Command accepted" }`. The SNS `RobotVerbosityChanged`
  fan-out is dropped (no SNS in Phoenix) — divergence, see below.

Errors keep the source codes/statuses: validation → `ValidationException` **422**
(`Boom.badData`, the hapi-style status the original service actually emitted), unknown
op → 404 `Method <op> not found.` (`Boom.notFound`), throttle 429, robot-only 403,
admin 401. Phoenix keeps its `__type` + `x-amzn-errortype` envelope (strictly more
informative than the original's plain Hapi payload, same statuses).

## Acknowledgment semantics (sync vs async)

Synchronous ack ops (PutEvents, PutBinary, NewKinesisCredentials, SetLevel) return the
result payload in the POST reply. Asynchronous ack ops (PutEventsAsync, PutBinaryAsync,
PutAsrBinary) return an upload grant (`uploadUrl` + object metadata); the robot performs
a separate raw PUT to that URL. Phoenix gives every `uploadUrl` a real destination: a
PUT endpoint on the classic entrypoint backed by a durable local `LogStore` (default
`$TMPDIR/phx-logs`, override `ETCO_classic_logDir`), with `url`/`GET /log/blob` making
the object retrievable — the same self-hosted pattern Backup already established.

   in the report above.
6. `robot.js`/`backup.js` validation errors use 400; the source Hapi services (incl. log)

   (not in scope).
