# N-08 default AST score candidate

Status: accepted as a bounded implementation after [independent root review](../evidence/2026-09-06/nlu-ast-ranking/root-review.json). Full N-08 remains open.

This candidate repairs one source-backed family in the default AST matcher. The
previous matcher charged every `$*`/`$wNN`/unknown-factory token `0.7`, while the
pinned native compiler emits a `1.0` heuristic for each wildcard byte, including
separators, then resets the weight after the complete wildcard. The candidate
uses UTF-8 byte prefixes for non-space wildcard cost and retains grammar-word
specificity. For ordinary unweighted full parses this gives an ordering offset
by an input constant from native wildcard cost. It is a bounded rank proxy,
not native numeric-score equivalence; explicit weights, factories, normalization
and equal-cost ties remain outside that relationship. The prefix keeps
the existing backtracking matcher bounded instead of rescanning every wildcard
span.

The source basis is ConvTech/jibo-nlu
`91b1bb6dbc702d3072df98a6fa0b76a6bc151d3e`: `parser/result_fst.cpp:75-80`
computes `input_string.length() - heuristic`, `parser/parser.cpp:124-134`
accumulates arc weights while retaining the lower heuristic, and
`compiler/compiler.cpp:175-182,201-215` defines a nonblank-character wildcard
followed by a space and `<1.0> ... <0.0>` weights. `compiler/list_manip.cpp:150-167`
and `:264-281` document UTF-8 word construction and top-rule separators. The
Pegasus consumer is pinned to
`5c0a7390539663ba749d360de348a428c088505c`; its
`RobustParserClient.ts:260-285` keeps the highest native result score and uses
request order only after score/tie filtering. The exact source/native hashes and
the existing isolated native control receipt are in
`.parity/reviews/n08-ast-family-20260906/provenance.json` and
`native-score-control.json`.

The full corpus replay below was run against this candidate's default AST
matcher under Node `v22.22.0`. This candidate did not launch the archived native
executable during the replay; `native-score-control.json` is the pre-existing
network-none native score control that establishes the cited compiler behavior,
with its image and validation hashes preserved in the provenance receipt. A
direct native full-corpus equivalence claim is therefore outside this candidate.

Against the preserved 295-difference default-AST evidence
(`.parity/reviews/n08-optional-root/full-parser-replay.json`, old candidate
`63bbddd63bcf72cefa601a4f8929efc1cc196df5`), a selected replay of all 295
previously failing rows produced 146 source-equal results, left 125 failures
unchanged, and changed 24 still-failing results. It introduced no request error
in the selected replay. The complete row-level receipt is
`.parity/reviews/n08-ast-family-20260906/selected-differential.json`; the
selected source-visible wins include `can you tell jokes` →
`requestTellJiboContent` and animal questions such as `are you a natterjack` →
`idle`. The changed-failure count is reported explicitly because this is a
bounded scoring repair, not a full grammar arbitration recovery.

The remaining source differences include rule-order/tie behavior such as
`what were you doing` (native `doesJiboHavePlansForEvent`, candidate
`whatDidJiboAction`) and unsupported/competing entity paths such as the

The existing loop-person test expectation was corrected to the pinned corpus's
`whoIsPerson` result, which includes `GivenName` before loop enrichment; this is
recorded in the candidate test diff rather than hidden as a matcher exception.
