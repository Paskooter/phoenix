## Candidate behavior

`packages/account/src/robotFace.js` now:

- resolves the Classic caller from the stored account matching the
  `Authorization: ... Credential=<accessKeyId>/...` value;
- applies the source robot-or-admin ownership check for `SuspendLoop`;
- applies the source admin-only gate for `SuspendRobotLoop` before friendly ID
  validation or lookup;
- distinguishes missing/deleted loops, missing robots, and robots without an
  active loop with their source error codes and statuses;
- validates the required string fields with a 422 validation response;
- persists `isSuspended` and a numeric `updated` timestamp before replying;
- exposes `isSuspended` and `updated` in `ListLoops`, filters deleted loops, and
  omits suspended loops from a robot's own list as the source controller does;
- emits a zero-length success for `SuspendRobotLoop`, matching the source
  handler's null output, and a command response for `SuspendLoop`.

This face remains the explicit legacy Classic/LAN compatibility boundary. It
does not verify the SigV4 signature, and it deliberately does not treat a
caller-supplied public `x-amz-credentials` header as an administrator identity.
The original internal gateway's translation from verified credentials to that
header is outside this slice. Exact Hapi/Boom versus AWS-JSON error-envelope
framing also remains qualified even though status and machine-readable code are
preserved for the Classic client.
