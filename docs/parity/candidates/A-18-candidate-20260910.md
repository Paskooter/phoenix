### OauthClients_20171108 (four ops)

Source-derived behavior, all four ops `@parseCredentials({adminOnly:true})`:

- **Auth (verified two-layer):** gateway `unauthorizedMethods`/`unsignedMethods`/
  `unactiveMethods` (43a692fe auth.ctrl.ts) contain **no** OauthClients target, so every
  request must carry a verified AWS V4 signature. The handler decorator then applies the
  `adminOnly` gate. Phoenix resolves the caller from the verified access key
  (`store.accountByAccessKeyId`); the admin gate reads `caller.isAdmin`, never the
  caller-controlled `x-amz-credentials` header (mirrors the established Loop/Account
  identity model). Missing/bad signature → the mapped SigV4 error (e.g.
  MISSING_AUTH_HEADER); non-admin → `AUTHORIZED_UNDER_ADMIN` 401 (exact code/message/
  status from srv-server@master src/errors.ts).
- **Controller (client.ctrl.ts):** `create` finds by clientId → `CLIENT_ALREADY_EXISTS`
  409; `aco.sourceId` falls back to `clientId` when aco is present without a sourceId;
  `update` finds by id → `CLIENT_NOT_FOUND` 404, assigns only defined fields, pre-save
  `updated = Date.now()`, `aco.sourceId` falls back to the stored `clientId`;
  `remove` uses findByIdAndRemove (returns null for a missing id — empty 200, no throw,
  wire body for that case unknown and recorded); `listClients` returns all rows.
- **Scheme (client.ts):** row → wire `{id, aco:{} default, clientId, pkce?, redirectUri,
  refresh (default true), secret?, created, updated, updatedBy}`, `_id` dropped.
  Scheme defaults applied on create: `aco.keepAliveTimeout 500`, `aco.recoveryTimeout 300`,
  `aco.version "1.0"`, `refresh: true`.
- **Payload validation (client.handler.ts Joi maps, srv-server@master validate.ts):**
  produced the exact Joi messages by executing the pinned-period Joi (`require('joi')` in
  the reference tree) over the handler's maps — including the fact that Joi **aborts on
  the first error in schema key order** and rejects empty strings even on optional
  fields. Phoenix emits the same `child "X" fails because [...]` messages on the Hapi 422
  Boom.badData envelope via the existing `sendValidationError` helper.
- **Persistence:** OAuth clients live in the account Store's new `oauthClients` collection
  (JSON-file store analog of the source Mongo `OauthClient` model). `create`/`update`/
  `remove` flush the store.
- **No event side effect** — the source `EventSender` is constructed but `create()` sends
  no event (observed from `index.ts` + oauth-clients mainline); Phoenix likewise sends none.

### Lps_20171201.NewCredentials

Source-derived:

- **Auth:** `Lps_20171201.NewCredentials` is absent from the gateway anonymous/unsigned/
  unactive lists → signature required. Handler `@parseCredentials({})` then requires
  `request.auth.credentials.friendlyId` or nvoced `ROBOT_ONLY` 403. In Phoenix the
  verified access-key account carries `friendlyId` for robot accounts, so the robot-only
  gate is `!caller.friendlyId → ROBOT_ONLY 403`, exact message `Request forbidden. Only
  robotd are allowed.` (typo "robotd" preserved from errors/lps.ts).
- **Controller (sts.ctrl.ts):** `assumeRole({ExternalId: \`${friendlyId}_${accountId}\`,
  RoleArn: config.server.lps.robotRole, RoleSessionName: \`${friendlyId}_${accountId}\`})`
  via an injectable `assumeRole` provider (Phoenix has no live AWS; the external seam is
  `createLpsStsProvider`). Response shaped exactly to the API model:
  `{bucketName, bucketPath, credentials:{AccessKeyId, Expiration, SecretAccessKey,
  SessionToken}, region}`. `bucketPath` matches the source template:
  `lps/robot={friendlyId}/account={accountId}/year={y}/month={m}/day={d}/session={ts}/`
  **including the source's 0-based month index** (`getMonth()`, no +1) — verified against
  the pinned controller.
- Unconfigured provider → explicit `LPS_STS_UNAVAILABLE` 503 (a clear unavailable
  boundary, like the settings provider errors), never a silent fake credential.

previous `UnknownOperation` 400 into real proxied traffic, end-to-end verified below.
