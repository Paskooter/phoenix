# I-01 candidate — Match all history HTTP routes and payloads

Date: 2026-09-10 · Branch: `ds/candidate-I-01-20260910` · Base: `06fb875`
Files owned: `packages/history/src/{index,query,store}.js` + test files.

## What this candidate does

1. **GET query variants.** Added `GET /v1/skill/launch/latest` and
   `GET /v1/skill/launch/count`, handling the IHQuery from the Express query
   string exactly like the reference handler (`addGetHandler('/latest', query =>
   ...)` consumes `req.query`). Phoenix runs the same Express 4.16.2 + qs 6.5.1 as
   the pinned Pegasus tree (`packages/utils/package.json` requires `express ^4.16.2`),
   so GET parsing is identical *by construction* — including the reference quirk that
   qs decodes array-rule leaf values as strings (so `value=0` cannot match an
   in-memory numeric `0`, in the reference as in Phoenix). Both routes also keep the
   POST variants the reference registers for both.
2. **Complete saved launch/payload records**: `POST /v1/skill/launch` now returns the
   full saved record (id, timestamp, sessionID, robotID, skillID, intent, personIDs,
   payload) instead of `{id}`, and does **not** compute `payloadSize` — Pegasus only
   attaches `payloadSize` on the payload-update path (`SkillLaunchCollection`
   `addSkillLaunch` never sets it; `saveSkillPayload` sets it to `Object.keys(...).length`).
   `PUT /v1/skill/launch/payload` returns the full updated record, or a raw `null` body
   (reference `res.status(200).json(null)`) when no record matches `{sessionID, robotID,
   skillID}`.
3. **No-match null case**: `latest` no-match is 200 `null` (never 404); count is
   `{count:0}`. Unknown routes keep the 404 `URL not found:` error envelope.
4. **Speech create/update**: `POST /v1/speech` -> `{id}` (timestamp defaults `|| Date.now()`).
   `PUT /v1/speech/:id` now a real Express param route (removed the old raw-server
   listener hack): updates only the eight whitelisted fields (`audioFileURL`, `asr`,
   `personIDs`, `nlu`, `match`, `redirect`, `skill`, `error`), strips `null`/`undefined`
   values, never erases existing fields, and an unknown id produces the 500 error
   envelope (the reference null-derefs `record._id` in
   `SpeechHistoryRecordsCollection.updateRecord` and Express turns that into a 500).
5. **Data shaping on write**: `personIDs` are sorted in place before save
   (`Preformatter.preformatSkillLaunchData`), so stored records match the reference.
6. **Rule default match**: rules without `match` get the first allowed method for the
   field/value pair (`validators/rule.ts` `ALLOWED_METHODS`), so queries the reference
   accepts are accepted here; `Unknown field:` / `Unsupported value type:` /
   `Cannot process this rule:` errors thrown before the defaulting already work.

1. **Launch records carry no computed payloadSize** (highest risk — inverts prior

## Candidate divergences for root

1. **Launch-record `timestamp` serialization**: Phoenix emits the same numeric ms the
   client sent; Pegasus stores a BSON Date and the record JSON carries an ISO-8601
   string (proven by the pinned speech test `new Date(time).toISOString()`). Phoenix's
   hub `evaluateIHRule` TimeSince computes `Date.now() - result.timestamp`, which works
   with ms and yields NaN with ISO (the Pegasus hub code is identical, so the reference
   TimeSince path is effectively latent-dead). Choosing ISO would require touching
   `packages/gateway` (not owned). Kept ms; needs integration decision.
2. **Healthcheck**: `createService` registers `GET /healthcheck -> 'ok'` before routes;
   the reference HistoryService overrides the response with
   `{status, skillLaunchDB, speechHistoryDB}` (200/500). Serving the DB-state shape
   would need a createService change (out of scope) — reported only.
3. `PUT /speech/:id` with an **empty/`text/plain` body** returns `{id}` here (body
   defaults `{}`) where the reference body-parser leaves `req.body` undefined and the
   handler throws (500). Client never does this.
4. Rule-validation **messages** for bad identifiers/dates/conflicting query conditions
   are I-02 scope (the current `Robot ID is required` 500 envelope already matches the
   builder-level throw).
