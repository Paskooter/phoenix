## Source basis

The frozen source is the prepared reference tree at
`.parity/reference/5c0a7390539663ba749d360de348a428c088505c`:

- `packages/baseskill/src/graph/mims/utils/slimmer/Slimmer.ts` calls the
  requester `SLIM`, `PLAY`, `LISTEN`, `DISPLAY`, and structural `Sequence`
  protocol builders. Error prompt selection compares `prompt.index` directly
  with `config.index`; `auto_rule_override !== null` is the fallback rule;
  question and optional-response MIMs pass `rule_name` to requester LISTEN.
- The pinned `jibo-command-requester` 4.0.6 implementation in
  `node_modules/jibo-command-requester/lib/jibo-command-requester.js` emits
  command IDs through `generateTransactionID()`: under Node it is a 32-character
  lowercase hexadecimal MD5 value. Its LISTEN shape is
  `{ contexts: Array.isArray(rules) ? rules : [rules], intents }`, its PLAY and
  SLIM optional fields disappear during JSON serialization, and Parallel emits
  `succeedOnFirst: false` by default.
- `packages/baseskill/src/GraphSkill.ts` records a framework `Skill Entry`
  event before entering every launch/proactive graph, with the five fixed
  properties used below. `packages/chitchat-skill/src/nodes/ProcessQueryNode.ts`
  and `src/utils/Analytics.ts` append `Chitchat Query` and `Chitchat Emotion`
  events after MIM selection.

Phoenix's response envelope and `GraphManager` session continue to use the
separate v4 UUID contract. Only generated JCP command nodes use the 32-hex
contract; prompt, view, domain, and session identities are not rewritten.

## Candidate changes

- Added `packages/skills/src/jcpId.js`, a small command-ID generator that
  returns 16 random bytes as 32 lowercase hexadecimal characters.
- Switched generated PLAY, LISTEN, DISPLAY, SLIM, SEQUENCE,
  SET_PRESENT_PERSON, and supplemental PARALLEL IDs to `newJcpId()` while
  retaining envelope/session `newMsgId()` calls.
- Changed both MIM LISTEN generation paths to emit `contexts: [rule_name]`
  and removed the non-source `rule` field. The direct JCP builder follows the
  same requester shape.
- Added `succeedOnFirst: false` to supplemental Parallel output.
- Matched Slimmer's exact Errors index comparison and its distinction between
  an explicit `null` auto-rule override (fall back to `es_auto_tagging`) and an
  omitted override (remain `undefined`, then disappear from JSON).
- Restored the framework launch analytics event and replaced Phoenix's
  chitchat-specific placeholder event with the source-backed query/emotion
  analytics fields. This keeps event ordering as framework entry first,
  skill-specific event second.

No MIM/resource bytes, comparator behavior, golden, reference, consumer, or
dependency files were changed.
