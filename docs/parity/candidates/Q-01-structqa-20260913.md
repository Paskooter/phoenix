## Request order, validation, and defaults

The source order is observable and is kept in the candidate:

1. Parse the JSON body and initialize `timestamps.receive_request`.
2. Parse `x-amz-credentials` as JSON. If it has an `id`, call
   `gqa.account.get_loop_id(id)` before routing any body fields. A missing or false loop id
   returns HTTP 200 with `message: "Missing robot_id!"`, `success: false`, `version`, and
   timestamps. The accepted account primitive can be supplied as `accountLookup` or an explicit
   account endpoint configuration.
3. Select the first `x-forwarded-for` value, split on the first comma, trim it, and otherwise
   use the request remote address.
4. `Intent == "News"` is selected before `Input` validation. `HasKid` is passed through source
   truthiness to the AP provider. A nonempty result is
   `{ success: true, source: "AP", response: { type: "array", payload: result } }`; an empty
   result is `success: false, message: "Empty news DB"`.
5. Other intents require an `Input` key. Missing input returns
   `message: "No Input field supplied in query"`. PII filtering runs before `clean_input`; a
   match returns `message: "Filtered by PII filter"` and retains the raw `input`.
6. `Intent == "Scripted"` cleans the text, calls API-AI with `(text, ipAddress)`, derives an
   intent pattern, and looks up a MIM. The response source is `"Scripted Response"`; a truthy MIM
   is `{ type: "mim", payload: mim }`, while an empty lookup is an ordinary no-answer. API-AI
   transport/JSON failures are an empty lookup. API-AI and registry seams are explicit because
   the source key and its `mimid_lookup.json` are unavailable in Phoenix.
7. `Intent == "GQA"` maps the country with `data.get("Country", "").lower()`: missing and empty
   strings map to `US`, known Jibo country names map to their ISO alpha-2 codes, and unknown
   nonempty strings map to `XX`. A non-string country therefore raises at the source `.lower()`
   boundary and reaches HTTP 500; it is not implicitly stringified. Latitude and longitude use
   source `str(data.get(..., ""))` semantics.
8. Every other intent returns `Unknown Intent 'None'` when absent, or the exact supplied value.

## Provider, fallback, and attribution behavior

The source GQA plan runs Bing and Wikipedia in parallel for three seconds, then Wolfram Alpha for
four seconds; late first-group answers remain eligible while the next group runs. Phoenix reuses
the accepted `createGqaProviderPipeline()` for the configured `providers` path, or accepts one
direct `gqaProvider` seam. Provider exceptions become ordinary no-answer results at this boundary.

The source test doubles show that provider selection uses Python truthiness of
`response.payload`: `false`, `0`, `""`, `[]`, and `{}` are no-answer values. A truthy payload sets
`success: true`; string answers receive a trailing period if needed. Bing and Wolfram Alpha
answers are inserted into the accepted attribution primitive with source, answer, URL,
`image_url`, and loop id. Wikipedia and AP/scripted results are not attributed by this code.

The candidate applies the same Python-like truthiness through `sourceTruthy()` and removes a
direct provider's empty/error shape before finalization, producing the source no-answer envelope.
A malformed provider response shape (for example `response: null`) remains visible as an HTTP
500 instead of being silently treated as empty.

## Response and raw HTTP framing

All normal route responses are HTTP 200 JSON text with version `5.2.15`, a final return timestamp,
and one of the source branch shapes above. No-answer responses have `success: false` and no
response payload; branch errors retain their source message. Handler/provider/shape exceptions
use the Flask-era HTTP 500 body shape `{ version, message, stacktrace }` with `text/html` framing.
Malformed or empty `application/json` entities use the Werkzeug/Flask 400 HTML body:

```text
<!DOCTYPE HTML PUBLIC "-//W3C//DTD HTML 3.2 Final//EN">
<title>400 Bad Request</title>
<h1>Bad Request</h1>
<p>The browser (or proxy) sent a request that this server could not understand.</p>
```

The HTTP route advertises loose JSON parsing for the source JSON content types and supplies the
same parser-error body. The Classic adapter test calls it with a real `{ req, res, body }` context,
so a future wire agent can register the adapter without reimplementing any branch logic.
