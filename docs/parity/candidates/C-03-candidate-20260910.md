## What was actually wrong

Three gaps, each reproduced before being changed:

1. **The reference config helper did not exist.** `packages/utils/src/config/EnvVars.ts:11-19`
   (`readEnvVars`) is the shared mechanism every reference config provider calls
   (`hub/src/config/HubConfigProvider.ts:24`, `lasso/src/LassoServiceConfigProvider.ts:13`,
   `history/src/HistoryServiceConfigProvider.ts:12`, `report-skill/src/EnvVars.ts:15`).
   Nothing in Phoenix implemented it; `packages/common/src/env.js` exported an
   unrelated `net()/etco()/boolEnv()` surface that only its own test called
   (VERIFIED by grep: the only consumers outside `env.js` are `env.test.js`).

2. **Two of the three reference registries could not be loaded.**
   `packages/hub/resources/skills/` ships `skills-local.json`, `skills-pegasus1.json`
   and `skills-pegasus2.json`. Phoenix bundled only the first, so
   `ETCO_hub_skillsConfig=skills-pegasus1.json` failed `ENOENT` instead of loading the
   unmodified reference registry (VERIFIED by `ls` on both trees before the change).

3. **The service executables ignored the source CLI contract.**
   Every reference service resolves its listen port as
   `parseInt(argv['p'] || argv['port'] || process.env.ETCO_server_port || '8080')`
   (`utils/common/run-service.js:8-38` + `hub/src/cli/start.ts:17-19`,
   `parser/src/cli/start.ts:16-17`, `report-skill|history|lasso|chitchat|template|example`
   `scripts/run-service.js`). VERIFIED by observation: before this change
   `ETCO_server_port=7391 node packages/gateway/src/index.js` bound
   `DefaultPort.gateway` (7010) and ignored the variable, even though
   `packages/contracts/src/constants.js` documents "Override with PORT or the
   service's ETCO_* var". The hub also printed no setup record and no help.

## Divergence candidates (not edited into DIVERGENCES.md)

1. **Per-service default port.** The source literal default is `'8080'` for every service;
   Phoenix's executable fallback is `DefaultPort.gateway|nlu|data|history|skills`
   (`packages/contracts/src/constants.js:124-133`), so a bare
   `node packages/gateway/src/index.js` binds 7010 rather than 8080. Source inputs (argv,
   `ETCO_server_port`) and `PORT` take precedence, and compose/reference environments set
   those, so the difference is only reachable for a bare local run. Changing it would make
   Phoenix's side-by-side services collide on one port, so I kept the adapter and made the
   precedence explicit. Recorded as a divergence, not silent.
2. **`lasso`/`history` config providers are not wired to `readEnvVars`.** The reference
   `LassoServiceConfigProvider.getConfig()` (`lasso/src/LassoServiceConfigProvider.ts:13-21`)
   declares seven **null** defaults — `ETCO_lasso_darkSkyKey`, `ETCO_lasso_googleMapsKey`,
   `ETCO_lasso_apNewsKey`, `NET_redis`, `ETCO_lasso_credentials_mongo`,
   `ETCO_lasso_credentials_dbName`, `ETCO_lasso_credentials_collectionName` — so the
   reference lasso *refuses to start* without them. `history/src/HistoryServiceConfigProvider.ts:12-21`
   has eight non-null defaults. `packages/data` currently reads a Phoenix-only
   `ETCO_data_credentialsFile` and no reference names. Those files are owned by D-01/D-02
   and I-01..I-03 (per `tasks.json`), not C-03, so I did not touch them; `readEnvVars` is
   now available in `@phoenix/common` for them to consume.
3. **Lasso's source help text is broken.** `lasso/scripts/run-service.js:9-12` calls
   `path.basename` in `printHelp()` without importing `path`, so `--help` throws
   `ReferenceError: path is not defined` inside the starter and the common runner reports
   that instead of usage. I did not reproduce the bug: `packages/data` prints the correct
   usage and then takes the source "Service didn't return promise" non-thenable path. A
   faithful reproduction would mean re-introducing a defect.
4. **Setup-log wording.** The source logs `Starting hub with config: ` plus an
   `util.inspect`'d object through `logging.Log('Hub')`; Phoenix emits the same message and
   the same field set as one structured JSON line on the `gateway` namespace. Per standing
   policy, log *wording*/format is not a parity gap; the field names, nesting and redaction
   are matched and asserted.
