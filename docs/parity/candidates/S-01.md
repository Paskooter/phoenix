# S-01 candidate: skill response timing and error envelope

Status: **bounded response-contract repair; awaiting lead review**

Owner: Luna Max
Base: `7d87cae`
Reference revision: `5c0a7390539663ba749d360de348a428c088505c`
Audit date: 2026-09-06

This candidate covers the response wrapper at the Pegasus `BaseSkill` /
`SkillService` boundary. It adds the source's measured `timings.total` to
successful Phoenix skill responses and preserves the source error behavior when
the handler rejects or returns an unsupported result. Graph transitions,
session persistence, and complete S-01 continuation parity remain outside this
bounded change.

## Source contract

The frozen source paths and hashes are:

| source | SHA-256 |
| --- | --- |
| `packages/baseskill/src/BaseSkill.ts` | `d5e70fafdafdd1e9ddd1a3f38ebe898283a95d7c478b91c260aed9dc9a288ed3` |
| `packages/baseskill/src/SkillService.ts` | `b2a240d1a0f7560a613457b133eea81ef20bf558a6bf3322c768be7c57df58bf` |
| `packages/utils/src/service/handlers/BaseHttpHandler.ts` | `d675e8e1756b1c5212c2b8db6d4efa9c4caa748cd2dd1f60893fd69ae449f385` |
| `packages/utils-common/src/Utils.ts` | `a239f3e578431f64b901088241a9d3f662790d8ff3de4c579baad0fe64198ea5` |

`BaseSkill` starts a real `Date.now()` timer immediately before awaiting
`handle`, then unconditionally writes `response.timings = { total: elapsed }`.
The write is inside the source `try` block. A rejected handler therefore
returns `buildErrorResponse(error)` without timings; a handler resolving
`undefined` or using a callback-style return fails at the timing write and is
also converted to an error response. `buildErrorResponse` contains `type`,
`msgID`, `ts`, and `data.message` plus `data.skill.id`; it does not add
`final` or timings. The source `getErrorMessage` converts strings directly,
uses `error.message` for Error-like values, and otherwise returns
`Error: ${JSON.stringify(error)}`.

`SkillService` mounts the `BaseSkill` handler at unauthenticated `POST
/v1/main`; `BaseHttpHandler` serializes both action and skill-error results as
HTTP 200 JSON. Common HTTP headers and byte framing remain owned by the shared
service contract work.

## Phoenix change

`packages/skills/src/skillService.js` now:

- starts and stops a real `Date.now()` timer around each valid handler call;
- overwrites any handler-provided `timings` object with the measured total;
- keeps the assignment inside the error-catching path, preserving the source
  `undefined`/callback failure boundary;
- localizes only the wrapper-generated assignment and null/undefined error
  conversion messages to the frozen Node 8 wording. TypeErrors raised inside a
  handler or a custom setter are returned unchanged; and
- uses a local source-equivalent `getErrorMessage` conversion for thrown
  strings and message-less objects.

The implementation does not use a fixed timing, inspect corpus IDs, or alter
graph/session behavior.

For object and function results it performs the source assignment directly.
It does not preflight descriptors or extensibility: inherited setters,
non-extensible objects with inherited setters, and Proxy assignment traps must
observe the same operation as the source. Only the primitive/null/undefined
wording conversion above is localized for the Node 8 wire contract.

## Request validation boundary

The existing Phoenix route validates `schemas.skillRequest` before invoking a
handler. The frozen `BaseSkill` wrapper itself performs no schema validation;
an invalid body reaches the skill's `handle` method and its result or thrown
error follows the normal wrapper path. This pre-existing Phoenix validation
difference is recorded separately and is not changed by this timing/error
repair. For the source fixture, `{}` reaches `handle` and returned a 200
`SKILL_ACTION` with measured timing; Phoenix returns a 200 `ERROR` with
`invalid SkillRequest: $.type: required property missing; $.data: required
property missing`. No claim is made here for malformed-request parity.

## Remaining scope and limitations

This candidate does not claim complete S-01 parity. Graph finalization,
subgraph transitions, trace/data mutation, invalid graph/session handling,
continuation across multiple HTTP turns, and cutover policy still require
separate verification. Error messages for JavaScript engine-generated
`TypeError`s raised inside handlers naturally use the running engine's wording;
the wrapper's own assignment and null/undefined conversion failures are the
bounded exceptions recorded by the source matrix. Shared HTTP response
headers and content length are not changed here.
