verified and does not claim the original streaming ASR contract.

## Candidate behavior

`packages/gateway/src/asr/audioDecoder.js` validates `LINEAR16`, `OGG_OPUS`,
and `FLAC` declarations and requires 16 kHz audio. LINEAR16 remains a direct
PCM path; odd network fragment boundaries are joined for VAD analysis and an
odd final PCM byte is rejected before WAV wrapping. OGG_OPUS is sent through a
persistent ffmpeg stdin/stdout stream and emits decoded signed 16-bit little
endian mono PCM as it arrives. FLAC metadata and CRC-checked frame boundaries
are parsed incrementally while one persistent `@wasm-audio-decoders/flac`
decoder emits signed 16-bit little-endian mono PCM before input EOF. Both
paths feed the existing Parakeet VAD before duration/EOS decisions and WAV
construction.

PCM is analyzed in bounded 10-ms (320-byte) windows, so decoded stdout chunks,
native 50-ms frames, and arbitrary network fragments produce the same VAD
events. The session retains partial samples between windows, cuts accepted WAV
PCM at the actual silence/max-buffer boundary, and flushes the remaining
accepted bytes only for explicit caller end-of-input.

Encoded input is bounded to 2 MiB of pending bytes, with 64 KiB child writes;
decoder/process errors reject the session with an explicit format/decode
error. `stop()` has two explicit lifecycle modes. A caller stop is
end-of-input: the decoder drains complete frames already accepted by the
session and drops only an incomplete encoded tail. VAD silence/max-buffer EOS
cancels the decoder at the detected boundary, so bytes queued after that
boundary cannot enter the WAV. The decoder settles `finish()` on every close,
abort, startup, format, and bounded-queue error. `OGG_OPUS` end-of-input also
requires a complete Ogg page with an EOS flag unless the caller explicitly
uses the end-of-input/truncated-tail mode. The `PHOENIX_FFMPEG` environment
variable (or `config.ffmpegPath` in focused tests) selects the OGG executable;
there is no silent missing-binary or decode fallback. FLAC has no executable
dependency: `packages/gateway/package.json` declares
`@wasm-audio-decoders/flac@0.2.11`, which brings
`@wasm-audio-decoders/common@9.0.7` and `codec-parser@2.5.0`. The workspace
lockfile is intentionally left for lead reconciliation; the runtime image
must install the gateway dependency and still provide ffmpeg for OGG_OPUS.

The deployable runtime is defined by [`scripts/Dockerfile`](../../../scripts/Dockerfile),
[`docker-compose.yml`](../../../docker-compose.yml), and [`.dockerignore`](../../../.dockerignore).
The image starts from `node:20-slim`, installs Debian `ffmpeg` and CA
certificates, sets `PHOENIX_FFMPEG=/usr/bin/ffmpeg`, and installs the workspace
manifest inside the image. Compose builds that image and keeps its installed
dependencies in a named `/phoenix/node_modules` volume after the source bind
mount. An isolated build tagged `phoenix-runtime:h07-5e24f6f` completed with
image ID SHA-256
`457adf87a1c4e6f6f5e7854406d197b7ea96930eca15e69357776bb7410d504e`; its
Debian ffmpeg is 5.1.9. The image's generated lock resolution recorded

## Focused evidence

The checked-in deterministic fixture is 300 ms of alternating 7,000-amplitude
speech followed by 1,000 ms of silence at 16 kHz mono. The raw PCM hash is
`095b97214735ad0450919e8105def5ad53f72df7586bca5a98b9123ab390d7c6`;
OGG_OPUS is 2,128 bytes with SHA-256
`89aa1b54a35f8c16aa1f7e40248a0fb658b69098fad1caab25c6f300c41cff52`; FLAC is
1,319 bytes with SHA-256
`9fbcd16ce81234f8998f21758410f4527a45ad71f94421e63fa6fc82223936ef`.
The FLAC decoder's complete output is byte-equal to the raw fixture, while
the OGG_OPUS integration checks decoded speech/trailing silence reaching VAD
and the WAV body. Tests split both formats across small arbitrary boundaries.

Focused command:

```text
node --test packages/gateway/test/asr.test.js
```

Result in the candidate worktree: 34 tests passed, 0 failed, 0 skipped under
Node `v22.22.0` with `/usr/bin/ffmpeg` 4.4.2. Coverage includes unchanged
LINEAR16 bytes, explicit-stop partial PCM retention, odd final PCM rejection,
unsupported declarations, bounded queues (including an active FLAC frame), malformed/truncated encoded input,
Ogg EOS validation, OGG_OPUS/FLAC decode before VAD on paced input, VAD
invariance across one large/native-sized/arbitrary PCM chunks, encoded fixture
VAD/output invariance, exact FLAC waveform output, every single-byte FLAC split
across metadata/frame headers, the 30-second max-buffer cut, zero-PCM/native-
error and pre-allocation output-bound regressions, and cancellation/resource
cleanup. The
paced tests use 10-ms writes with bounded 3-second waits and record the source
byte count at the first decoded PCM/SOS event. The full gateway test command
(`node --test packages/gateway/test/*.test.js`) passes 54 tests.

The persistent FLAC path creates zero child processes. Three runs of the
1,319-byte deterministic fixture, paced in 17-byte writes every 10 ms, emitted
the first PCM at byte 289 in 164–174 ms and produced all 41,600 bytes
byte-for-byte equal to the raw fixture. The paced OGG fixture still produced
its first PCM at 2,048 of 2,128 source bytes in about 320 ms, and the session
reached SOS at the same source boundary.

The lead supplied two private native captures for read-only validation; their
raw audio is not committed here. At the recorded native pacing, the 106,060-
byte OGG capture (26 records over 12.889 s) emitted PCM at byte 4,333 in about
449 ms and produced 415,360 bytes whose SHA-256 was
`d3ca73d9eaf7e64080ec941654771e77a8d2af04f9c73695780009e07972f092`, exactly
matching the ffmpeg reference. The 165,020-byte FLAC capture (52 records over
12.464 s) emitted PCM at byte 6,828 in about 471 ms and produced 401,408
bytes whose SHA-256 was
`fc94db1b784c9cf3014353330c0a9acba5c062caca8690b85eda674268dee1c5`, exactly
matching the ffmpeg reference. The OGG capture has no EOS page, so this check
used the explicit truncated-tail end-of-input mode; caller `stop()` selects
that mode. The decoded native PCM had maximum 20-ms RMS values of 106.37
(OGG) and 103.61 (FLAC), with no frame above the 400 speech threshold.

Using the immutable recorded wire timing from the lead's baseline capture, two
repeat runs delivered all 26 OGG records and 52 FLAC records to concurrent
`ParakeetASRSession` instances. OGG first PCM was at source byte 4,333 in
447–448 ms; FLAC first PCM was at byte 6,828 in 461–485 ms. Both sessions
remained below the RMS 400 speech threshold, fired zero SOS callbacks, reached
`DONE` after `stop()`, and left `decoder`, `decoderError`, and pending encoded
bytes clear. One earlier combined replay produced an OGG callback at 34,004
bytes/4.108 s while the FLAC replay was initializing; that outlier was not
reproduced in these repeats, so startup contention remains a bounded risk to
measure in lead hardware tests. The pre-SOS stop calls intentionally cancel
the encoded tail, so these partial session buffers are not used for the full
waveform hash comparison above.

Two additional direct OGG replays emitted at byte 4,333 in 444–445 ms and
produced the complete reference hash above. Input options `-analyzeduration 0`,
`-analyzeduration 100000`, and `-probesize 32768` were byte-identical and had
the same first-output boundary; `-fflags nobuffer` lost 640 PCM bytes and was
rejected. The checked-in speech fixture reached first PCM and SOS at source
byte 2,048 in 337–338 ms, well before its 5-second SOS timeout.

## Remaining H-07 acceptance

This is a bounded encoding repair only. Original Google streaming/interim
results, FastEOS/earlyEOS, annotations, language/provider behavior, timeout
semantics, and complete upstream failure parity remain open. The deterministic
fixtures and private native captures establish decoder/lifecycle behavior;
they do not establish the original provider contract. Root must review the
candidate, compare the original provider, and perform live hardware checks
before changing the H-07 ledger.
