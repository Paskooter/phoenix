# A-02 candidate: signed Classic authentication and hub-token issuance

Status: bounded root-reviewed candidate; full A-02 and native end-to-end acceptance remain open.

Root's [Node 8 network review](../reviews/a02-root-node8/README.md) supersedes the previous modern-host Keep-Alive expectation. All 20 invalid-body cases now match original Node 8 status, decoded body and complete headers with only Date normalized. Fixed-time original/Phoenix tokens are byte equal; the corrected integrated unit suite passes 376 tests. Historical evidence generators are preserved under `packages/account/tools`; their superseded assertions are outside automatic unit discovery.

This candidate implements one source-observable sensitive operation: a signed `Account_20151111.CreateHubToken` request. Existing OOBE, Loop, Settings, and OTA compatibility handlers retain the explicit LAN-trust behavior already used by Phoenix. Broader gateway dispatch, permissions, credential rotation, and every account operation remain open.

## Source pins and call path

- Security gateway: `jiborobot/srv-security-gw@43a692fe7670660aaed6ab5979c6c83039eb711c`.
  - `src/auth.scheme.ts` invokes `AuthController`, then redacts `secretAccessKey` to `***hidden***` in forwarded credentials.
  - `src/controllers/auth.ctrl.ts` enforces `AWS4-HMAC-SHA256`, the `Date`/`X-Amz-Date` clock window, access-key lookup, active-account checks, and exact V4 authorization comparison.
  - `src/v4.js` supplies canonical URI/query/header/body hashing and the HMAC key chain.
  - `src/util.js` delegates query parsing to Node `querystring`, sorts duplicate values, and uses ASCII lower-case header ordering.
  - `src/routes/gw.route.ts` forwards the stream and `X-Amz-*` headers and adds `x-amz-credentials` as gateway metadata. Phoenix never treats that public header as verified identity.
  - `src/errors/account.ts` supplies the error codes/messages used by the candidate.
- Account service: `jiborobot/srv-account-ws@b525601390108b8635a31794dfa5cc3fda8a37d0`.
  - `src/handlers/account.handler.ts` maps `CreateHubToken` and obtains the caller from parsed credentials.
  - `src/controllers/account.ctrl.ts` resolves the account with its own `findById`, then passes the Mongoose document's `accessKeyId`, `email`, `friendlyId`, `id`, `payload`, and `secretAccessKey` to `TokenController`; the account schema has no `select:false` on `secretAccessKey`.
  - `src/controllers/token.ctrl.ts` signs an HS256 token and returns an epoch-millisecond expiry for three hours.
- The account schema's `toJSON` transform redacts credentials only for serialized account responses. It does not run when `account.ctrl.ts` reads the document fields for `CreateHubToken`.
- Native client: `jiboV2/jetstream@01ae81fc366ccd6e68ca66fa98f77f957dcdb1fb`, `jibohub-client/src/Authentication.cpp`.
  - It signs an empty `POST` request for service `jibo` before attaching `{}`, `Content-Type`, `Content-Length`, and `X-Amz-Target: Account_20151111.CreateHubToken`.
- JS source signer fixture: archived `aws-sdk@2.205.0` in the prepared reference, with the matching `srv-jibo-server-client` V4 signer behavior.

## Candidate behavior

- `packages/common/src/sigv4.js` provides source-compatible V4 canonicalization, HMAC signing, strict greater-than-15-minute clock skew, exact source error categories, and a resolver-based verifier. Only the access key in the Authorization credential is sent to the resolver; `x-amz-credentials` is ignored for identity.
- Explicit `x-amz-content-sha256` follows the archived gateway's source behavior. Without that header, the verifier hashes the exact received bytes. This preserves the native sign-before-body path without a blanket empty-body exception.
- `packages/common/src/service.js` captures body-parser's exact post-inflation bytes in `req.rawBody` for JSON and form requests. `packages/classic/src/router.js` forwards those bytes and the signed headers. It uses `http.request` so the original signed Host survives the Classic-to-account hop; undici/fetch rewrites Host to the upstream URL.
- Account `CreateHubToken` verifies SigV4 against the local account store, requires the configured hub secret, and issues the source-ordered three-hour HS256 claim object: `accessKeyId`, `email`, `friendlyId`, `id`, `payload`, and the account's real `secretAccessKey`, followed by `iat` and `exp`. The returned expiry is epoch milliseconds. Gateway `auth.scheme.ts` redacts its forwarded credential envelope after authentication; that redaction does not replace the JWT claim.
- The portal's two-argument `/api/token` helper remains separate: it omits `email`, `payload`, and `secretAccessKey`, and retains its prior second-boundary expiry (`expires === exp * 1000`). Existing LAN-trust OOBE/Loop handlers continue to use their compatibility lookup path and are documented as outside this bounded authentication candidate.
- `CreateHubToken` payload validation follows `@jibo/server`'s `@validatePayload({payload: Joi.string()})` with `allowUnknown: true`: omitted payload becomes `null` through the controller default, while explicit `null`, empty, and non-string values return Hapi/Boom 422 JSON (`statusCode`, `error: "Unprocessable Entity"`, `message`). Unknown object keys remain accepted.
- The Account and Classic boundaries opt into non-strict JSON parsing only for `CreateHubToken`, allowing Joi to classify top-level `null`, arrays, numbers, booleans, strings, and an omitted body. The common service remains strict by default. Account's validation response uses the exact Joi messages and Hapi/Boom headers (`application/json; charset=utf-8`, `cache-control: no-cache`, `vary: accept-encoding`); the Classic proxy forwards those headers and removes Express's `x-powered-by` for this 422 response. Signed bytes remain the verifier/proxy input, including an empty entity.
- Classic rejects compressed proxied entities with a visible 415 response because body-parser exposes post-inflation bytes while the signed content headers describe the compressed wire entity. Proxied upstream requests have a bounded absolute lifecycle deadline (10 seconds by default, capped at 60 seconds), retain the socket-inactivity timeout, and surface aborted responses as 502.

Root removed the unrelated Account-to-OTA forwarding edits and restored that function byte for byte from the pre-A-02 implementation. OTA behavior remains owned by A-08; this bounded authentication change does not alter it.

## Remaining A-02 boundaries

The pinned original SDK signer and source-reconstructed native sign-before-body request have been exercised through ephemeral Phoenix listeners, but the native C++ binary and an original service have not been run. The security gateway's upstream account route and its redacted internal credential envelope are not reproduced as a separate process; Phoenix verifies the signature at the account boundary and preserves the original Host across the direct Classic hop. The original Node 8 handler/controller/WebToken path was source-traced against pinned `@jibo/server`/`jsonwebtoken` behavior; no production credentials were used. A full original service fixture was not started here. Pre-signed URL query mutation remains outside the authenticated `CreateHubToken` path, although its `presigned-expires` header classification and the source's s3 path rule are covered by signer fixtures. Gateway registry routing, anonymous/unauthorized method policy, account permission checks beyond the issuing account, key rotation, gateway-side credential caching, and the remaining Account/OOBE/Loop operations remain open. This candidate is not a parity verification claim.
