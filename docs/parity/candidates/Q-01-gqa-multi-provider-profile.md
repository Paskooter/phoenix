# Q-01 multi-provider GQA profile

This candidate adds an explicitly selected GQA service profile that wires the
reviewed Bing, Wikipedia, and Wolfram Alpha adapters into the recovered
`SERVICE_PATTERN`: Bing and Wikipedia run together for 3 seconds, followed by
Wolfram Alpha for 4 seconds. The default Phoenix skill registry and gateway
registration remain unchanged. A caller must select
`PHOENIX_GQA_PROFILE=multi-provider` and provide the three endpoint values;
there are no provider URL fallbacks.

The integrated branch is based on Wiki runtime
`76ba31bd3765b9ab05ed859609439f42013332d0` and contains only these provider
commits in addition to that base:

* Bing `d3bc6ffa12395b9592750b53f0dedcb69c96925c` (cherry-picked as `db9a2fa`)
* Wolfram Alpha `af2e04e54b500a26e9345a00b9dec4f089ea155e` (cherry-picked as `fc73040`)

The profile implementation is
`packages/skills/src/gqaMultiProviderService.js`. It exports a factory for
the profile, a configuration reader, and an opt-in listener. The host
`start()` path selects it only for the exact `multi-provider` profile and
accepts `answer`/`answer-skill` as the selected skill. The gateway resource is
`packages/gateway/resources/skills/skills-gqa-multi-provider.json`; it is an
explicit resource and is not added to the default registry.

## Open scope

The source route performs an Account loop lookup for every successful
HTTP-route case and inserts Bing/Wolfram attribution records on successful
answers. This profile reads the source account fields and preserves provider
URL/image output, but it does not invent an Account transport or attribution
store. Those are explicit deployment seams and receive no parity credit here.
The source control also names the Python `unidecode` package as a seam; the
candidate Bing adapter uses its reviewed built-in fallback, so non-ASCII
unidecode equivalence is unverified. The source Wikipedia package's internal
HTTP request is likewise a named package seam in the source control; the
candidate retains the recovered MediaWiki request parameters and captures
them, but this run does not claim a source-package wire comparison.

This is an unverified, opt-in provider integration candidate. It does not
claim real-provider reachability, full attribution/account parity, or
whole-task Q-01 completion.
