# Q-01 — Source-backed GQA answer contract slice

Status: **working candidate; unverified**  
Owner: Luna Max  
Follow-up base: `3f0efc4488ecc9aa011cdcb79bbe8072fad4ea28`
Source: `jiborobot/srv-gqa-ws@ebe1a7d38f511570060c1fbf61bec89d58419b26`

This candidate adds an explicit source-registration profile in
`packages/skills/src/gqaAnswerSkill.js`. The existing Phoenix
`answer-skill` handler and shared registry stay unchanged. A caller can host
`gqaAnswerSkill` with the original `answer` registration and inject a local or
live provider through `createGqaAnswerSkill({ provider })`.

The provider seam returns the source `GqaParallelQuery` result shape:

- `{source, response: {payload, ...}, type?, url?, timings?}` produces one
  source `SLIM`. A missing final period is appended as in
  `gqa.py:638-655`.
- `{}` produces the weighted question-specific/generic no-answer MIM with the
  source `DISPLAY` view and cleaned query text.
- An explicit provider `{message}` produces the source `GQA_error` MIM;
  provider details stay server-side. A rejected provider call follows the
  original `GqaParallelQuery` behavior: the call is recorded privately and,
  when no provider succeeds, the response is the normal no-answer MIM.

The response builder follows `gqa.py:401-419` and `673-710`: JCP IDs are
32-character command IDs, response IDs are UUIDs with hyphens, the action
contains one `SLIM`, `data.skill` is `{id: "answer", version: "5.2.15"}`,
analytics is keyed by `answer`, and `final`/`fireAndForget` are true. The
question map and cleaning boundary follow `gqa.py:537-585` and
`gqa/nlp.py:clean_input`. All ten recovered GQA MIM files are vendored under
`packages/skills/resources/mims/gqa/` with their source prompt inventories.

The provider seam is intentionally narrow. It does not reproduce the
original Bing, Wikipedia, Wolfram Alpha, attribution database, or banned-word
services. A production adapter must supply those dependencies; the default
factory has no provider and therefore exercises the source no-answer path.
The follow-up does implement the source IP and PII request blocks before
providers. Account loop lookup and provider-specific attribution remain
unimplemented. When this handler is passed through Phoenix `skillRoute`, the
common wrapper overwrites detailed source timings with its own `total`; the
standalone factory response retains the source timing fields.

The follow-up also exports `createGqaProviderPipeline({ providers })` for an
explicit local adapter profile. It starts the Bing/Wikipedia group together,
selects in source priority order, and tries Wolfram Alpha after that group
has no payload. Adapter exceptions become private failed results and fall
through to no-answer. The helper does not claim the source's 3/4-second
wall-clock timeout behavior; a deployment adapter must add and test that
policy around real provider transports.
